# Миссия агента

## ФИО: 

Курин Андрей Арсеньевич

## Задача

Задача №1 / Алгоритмы

Поиск маршрута в ориентированном графе временных коридоров. Нужно определить выполнимость миссии, минимальное личное время агента и максимальную выгоду от собранных артефактов.

## Сборка

Требуется компилятор g++ с поддержкой C++17.

Команда сборки из каталога проекта:

g++ -std=c++17 1.cpp

## Запуск

Сохраните входные данные в input.txt и выполните:

./a.out < input.txt

Либо же заупустите:

./a.out

И затем введите данные последовательно как указано в формате данных ниже

## Формат ввода

Сначала вводятся n и m: количество вершин и коридоров.

Затем вводятся T_lim и T_cost: крайний момент завершения миссии и количество единиц личного времени, которое агент оценивает в один талон.

Далее вводятся стартовая вершина in, количество выходов num_out и номера выходных вершин.

После этого задаются m коридоров. Для каждого вводятся from, to, len, deadline, req_count и req_count номеров необходимых предметов. Для коридора без отдельного срока можно указать deadline, равный T_lim.

Затем вводится количество предметов k. Для каждого предмета задаются where, cost, from и to: вершина, ценность, начало и конец окна доступности. В выбранном формате обе границы окна указываются всегда.

Вершины и предметы нумеруются с нуля. Номер предмета соответствует его порядку во входном списке и не обязан совпадать с номером вершины.

## Формат вывода

Если миссия невыполнима, выводится NO.

Иначе выводятся три строки: YES, минимальное личное время и максимальная выгода. Последнее значение является вещественным числом.

## Принятые решения по условию

Изначально агент находится в мировом времени 0. Перед входом в граф он выбирает стартовое время s и тратит на перемещение модуль s единиц личного времени.

Достаточно рассматривать s не больше нуля: положительный старт заменяется стартом в нуле с ожиданием. Если завершение произошло в мировое время t, личные затраты равны t - 2*s.

В вершинах разрешено ждать. Длительности переходов целые и неотрицательные. Срок коридора проверяется по моменту окончания перехода. T_lim ограничивает мировое время завершения миссии.

Собирать предметы необязательно. Выходную вершину можно посетить и продолжить маршрут, если агент пока не завершает миссию.

За предметы начисляется их суммарная ценность V. Выгода считается как V - personal_time / T_cost. Это оценка награды с учётом личного времени. Если все допустимые варианты дают отрицательную выгоду, выбирается наибольшая из них. Маршруты для минимального времени и максимальной выгоды могут различаться.

## Алгоритм

У нас есть состояние поиска, оно состоит из вершины и битовой маски собранных предметов. В виде маски также представлены требования каждого коридора.

Prepare строит списки исходящих и входящих рёбер, распределяет предметы по вершинам и вычисляет маски требований.

Для фиксированного старта обычная Дейкстра находит самый ранний момент прибытия в каждое состояние.

Для выбора старта мы ищем контрольные точки на сроках коридоров, закрытиях окон предметов и окончании миссии. Обратная Дейкстра определяет самый поздний старт для достижения каждой точки. К найденным стартам добавляется ноль.

Обычная Дейкстра запускается для каждого различного стартового момента. Для каждого итогового набора предметов сохраняется минимальное личное время, после чего вычисляются три ответа.

Собственная двоичная куча Heap используется как очередь в обеих Дейкстрах. В обратной Дейкстре приоритет равен отрицательному мировому времени. std::set используется отдельно для удаления повторяющихся контрольных точек и стартов.

## Ограничения

T_cost положителен. Число предметов небольшое и меньше 64. Индексы вершин и предметов корректны. Времена, суммы длительностей, личные затраты и промежуточные временные значения по модулю меньше 10000000000000000.

Число состояний равно n * 2^k. Из-за перебора контрольных точек и повторных запусков поиска в худшем случае появляется множитель порядка 4^k по числу предметов. Решение рассчитано на небольшое k.

## Асимптотика

Обозначения: n - количество вершин, m - количество коридоров, k - количество предметов, q - количество выходов.

Расширенный граф содержит n * 2^k состояний и не более (m + k) * 2^k переходов.

Один запуск обычной или обратной Дейкстры занимает O((n + m + k) * 2^k * log(2 + (n + m + k) * 2^k)) времени.

Пусть P - число различных контрольных точек. Оно не превышает (m + k + q) * 2^k. Обратная Дейкстра запускается P раз, обычная — не более P + 1 раза.

Общее время работы: O((P + 1) * (n + m + k) * 2^k * log(2 + (n + m + k) * 2^k)).

В худшем случае: O((m + k + q + 1) * (n + m + k) * 4^k * log(2 + (n + m + k) * 2^k)).

Дополнительная память: O((n + m + k + q) * 2^k). Учитываются состояния, контрольные точки, стартовые моменты и очередь поиска.

## Пример 1

Пример из условия с принятыми в проекте правилами.

### Ввод

5 7  
120 10.0  
0 2  
3 4  
0 1 5 120 0  
1 2 20 120 0  
2 0 10 120 1 1  
0 4 0 120 1 1  
0 3 20 120 0  
3 1 10 120 0  
3 2 5 120 0  
3  
3 2 0 10  
1 2 30 40  
4 8 0 80  

### Вывод

YES  
20  
4  

### Пояснение

Минимальное время даёт маршрут 0 -> 3 без предметов со стартом в момент 0.

Для максимальной выгоды можно пройти 0 -> 1 -> 2 -> 0 -> 4. В вершине 1 необходимо ждать с момента 5 до момента 30. Личные затраты равны 60, ценность предметов - 10, выгода - 4.

## Пример 2

Маршрут с ожиданием появления предмета, необходимого для следующего коридора.

### Ввод

3 2  
10 2.0  
0 1  
2  
0 1 3 10 0  
1 2 2 10 1 0  
1  
1 5 5 8  

### Вывод

YES  
7  
1.5  

### Пояснение

Агент стартует в момент 0 и приходит в вершину 1 в момент 3. Предмет доступен с момента 5, поэтому агент ждёт 2 единицы времени. После подбора он проходит в вершину 2 и завершает миссию в момент 7.

Личное время равно 7, ценность предмета - 5, выгода равна 5 - 7 / 2 = 1.5.

## Проверка

В примере из условия есть противоречия между временными окнами и приведённым ответом. При принятой трактовке минимальное время равно 20, максимальная выгода равна 4.
